Feature coverage for deployed workloads

GTX2 is built around the functions teams actually deploy: distributing traffic, enforcing policy, sitting in front of application servers, and carrying storage-heavy flows on the commodity x86 hardware you already run.

Load balancing

Spread connections across backend pools entirely in userspace, keeping latency and CPU overhead predictable under high concurrency.

HTTP throughput validated at 82 to 90 Gbps

Firewall

Apply stateful filtering directly in the data path instead of bouncing packets through the kernel, so policy enforcement keeps pace with forwarding.

L3 forwarding validated at 200 Gbps on 1 core

NAS

Use the same high-throughput packet path for storage-heavy east-west traffic and NAS-facing nodes without carving out a separate appliance tier.

Runs on the same commodity x86 footprint as the rest of the fleet

nginx support

Deploy GTX2 in front of nginx or alongside it, keeping the existing HTTP stack while offloading the traffic handling that usually burns kernel time.

HTTPS validated at 61 to 74 Gbps with QAT assist

How it shows up in production

Edge load balancer

Front multiple application pools with userspace connection distribution, then leave nginx or origin services unchanged behind it.

Inline firewall

Keep security policy and forwarding on the same software path instead of splitting routing and filtering across separate boxes.

NAS front end

Place GTX2 in front of NAS-heavy services where throughput matters more than appliance branding and keep operations on standard Intel servers.

nginx acceleration path

Put GTX2 next to nginx when you want to preserve the application-facing stack but remove the kernel bottlenecks in front of it.

Scale features by core, not by appliance

Whether the node is fronting nginx, enforcing firewall policy, or handling storage-heavy traffic, performance scales linearly with core count from Intel Atom through Xeon Scalable. No specialized hardware required.
